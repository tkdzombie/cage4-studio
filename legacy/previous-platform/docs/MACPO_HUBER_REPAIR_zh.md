## 确认的问题

此前“有限值、真实更新、成本单位正确”只覆盖部分工程性质，不能证明完整算法适配无错误。本轮直接定位到锁定作者实现的Huber损失：

```python
a = (abs(e) <= d).float()
b = (e > d).float()
```

当残差`e < -d`时，两个分支都为零，损失和梯度错误地为零。标准Huber的线性尾部应覆盖`abs(e) > d`。例如`e=-20, d=10`，旧损失为0，正确值为150；若预测值为0、目标为−20，对预测值的正确梯度是+10。

新OT任务使用完整回合MC回报，较大的负残差会触发此分支。MACPO fraction1的cp256在固定四开发场景、1996个状态中的reward负尾残差比例为各agent约62.02%–62.88%。该错误会丢掉这些状态的拟合信号。另一作者分支也有同源helper，但本轮只修复和训练MACPO。

此前OT训练使用旧实现4f4d7072ab16f4ff2e0abbe07ff9754bb5d4bd88cb2741d2b811ae9f3d38247d，结果与权重完整保留，须注明受此适配缺陷影响；不能把它们作为正常MACPO学习失败或环境不可学习的充分证据。旧均值成本实验是否及多大程度触发同一负尾分支尚未逐状态审计，不追称旧版本已完整正确，也不修改其历史成绩。

## 先否定假设，再修复明确错误

固定诊断先比较作者价值clipping开/关：四开发场景固定策略采样1996步，原策略不更新；前两场景拟合、后两场景保留，只训练并丢弃critic副本。每agent的reward/cost两类critic、两个选项、各20步，共400次副本优化。

| 诊断 | 保留场景reward MSE均值 | 保留场景cost MSE均值 |
|---|---:|---:|
| 原损失，clipping开 | 459.2449 | 0.153068 |
| 原损失，clipping关 | 476.1813 | 0.136460 |

取消clipping没有改善任何一个agent的保留场景reward MSE，未通过事前限定的候选门槛。因此没有用这项开关继续训练或扩大扫描。

利用同一私有缓存，零新增transition，再比较原Huber与正确的对称Huber；保留clipping和所有原优化器设置。20步副本拟合后的reward MSE为459.2449→452.3750，cost MSE均为0.153068。数学错误被明确修复，但短拟合改善有限，不据此宣称所有学习问题已解决。

两个诊断均保持原五actor和两类critic的权重指纹不变。副本及缓存开发数据不用于baseline初始化，不上传原始数据或模型。
